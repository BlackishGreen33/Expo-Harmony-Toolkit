# v1.11.4 验收记录（publication-state reconciliation）

- 版本：`1.11.4`
- 发布轨：`latest`
- 范围：对账 `v1.11.3` 的发布状态，更新版本与长期发布文件，不扩大 `verified` 或 public API

## 结论

`v1.11.4` 是 publication-state reconciliation patch：它把 package、toolkit 常数、双语 README、roadmap、support matrix、CLI 构建说明与 npm 发布说明对齐到同一版本口径，同时把易腐化的精确远端状态移入版本 acceptance。

- 不新增 CLI 命令
- 不修改 `DoctorReport`、`CapabilityDefinition` 或 `nextActions[]` wire shape
- 不把 preview / experimental capability 提升到 `verified`
- 不把 debug/release HAP build pass、simulator install/start 或 app-shell smoke 表述成真机 device pass 或 per-capability runtime pass

## 发布状态对账

| Surface | `v1.11.3` 对账结果 | `v1.11.4` 记录 |
| --- | --- | --- |
| 初始 readiness | 未创建 tag、发布 npm 或创建 GitHub Release | 历史状态保留在 `v1.11.3-acceptance.md` |
| 后续发布 | security commit 后已发布 npm、tag 与 GitHub Release | 不重打或移动 `v1.11.3` tag |
| 长期发布文件 | 不保留会腐化的 npm dist-tag 或“尚未发布”现况句 | 精确远端状态只留在 acceptance |

## 本地验证证据

- 聚焦 Jest、TypeScript build、tarball 文件清单检查与 release dry-run 的实际命令和结果由本 release commit 的任务报告记录
- `release:check` 以 `EXPO_HARMONY_RELEASE_SKIP_HAP=1` 执行时只跳过真实 DevEco HAP 构建；其余 tarball 安装 smoke、`doctor --strict`、`init --force` 与 `bundle` 仍应完成

## 发布证据

以下远端动作由 controller 在本地 release commit 后执行；本地对账不执行 npm、GitHub、tag 或 push 操作：

| Surface | 所需证据 |
| --- | --- |
| Git tag | `v1.11.4` 指向 release commit |
| npm | `expo-harmony-toolkit@1.11.4` 发布到 `latest` |
| GitHub Release | `v1.11.4` Release 已建立 |
| GitHub Actions | tag 触发的 release workflow run 已记录 |

## 验收边界

- 本记录不要求真机 device evidence
- 本记录不关闭 release HAP runtime evidence
- 本记录不改变 npm `latest` / `next` 的 capability promotion 规则
- `v1.11.3` 的初始 readiness 与后续发布状态都保留在其自身 acceptance，不重写历史
