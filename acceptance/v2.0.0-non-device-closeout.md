## 結論與邊界

七個 source-fresh project 都安裝同一路徑、同一 SHA-256 的 packed tarball，通過 installed-package contract、parsed doctor、forced init、兩次 forced sync、bundle marker、debug HAP 與 release HAP build。七個 project 也都取得 simulator basic-runtime pass；其中 `official-native-capabilities` 與 `official-wave-b` 的原始 signed release HAP 因 signing profile 無法授予 restricted permission 而安裝 blocked，simulator 欄位的 pass 來自明確標記的 temp-only permission-removed variant。

Route catalog 的結論是 `19/19 route stability pass`、`16/19 functional/fallback pass`、`3 個 action blockers`。全部19條route都實際導航到exact marker，route後process/ability存活且corrected fatal matcher為0；這不等於19個functional action全通過。三個blocker是public `/gesture-handler` 的 RectButton callback、`file-system` 的write/read/cleanup action群組，以及Wave B media-library permission action。

`simulator pass 不是 device pass`。本記錄不提升任何 public support tier，不修改 `DoctorReport`、`CapabilityDefinition`、public wire format 或 `CapabilityEvidence.release/device`。相機擷取、真實相簿選取、GPS、推播到達／點擊、真實 media-library 讀寫、原生 screens 與 Skia surface 等真機語義保持 deferred（文件契約：`真机语义保持 deferred`）。

### file-system blocked evidence

只使用有界且互不重複的 automation 方法，沒有盲目重跑：

1. 初始 UI runner在捲動後點擊 `Write UTF-8 file`；按鈕列仍有 scroll movement，沒有可辨識 result text，立即停止該 action chain。
2. 精準 correction先等待 bounds 連續穩定；Write clickable父節點連續兩次為 `[162,672][1110,812]`，viewport為 `1272×2772`，單次 tap `(636,742)` 完整落在 visible/enabled/clickable父節點內。tap後按鈕列上移136px且無新增或移除 result text。另獲准的 cleanup-only單次 tap，其父節點為 `[162,1864][1110,2011]`、tap `(636,1938)`，結果同樣無 `Cleanup OK`；不再重試座標點擊。
3. SDK-documented keyboard method送出兩次 `KEYCODE_TAB=2049` 並逐次 dump；focus始終停在同一 root node，沒有可觀察 focus變化，因此沒有送出 `KEYCODE_ENTER=2054`。

第一步只證明 sandbox directory建立成功。UTF-8 write、read full與sandbox cleanup未證，不得寫成 functional pass。保留的 temp evidence包含 stable/result UI tree、focus probe與tap後 screenshot；第一個 correction 的tap前 screenshot未由 runner捕捉，只有tap前 stable UI tree，這是明確 evidence gap。

### media-library blocked evidence

`Inspect media permission` 點擊前顯示 `Permission lookup has not run.`；點擊後該文字消失，但沒有出現 `Media permission status=...`、可辨識 error/cancel/denied文字或 system permission dialog。Route marker、process、ability與fatal=0仍通過，因此只記 route/stability pass、permission action blocked，不修改 source/HAP來美化本輪證據。

### gesture-handler callback boundary

Public route identity是 `/gesture-handler`。Source/smoke contract只證明route使用RNGH 2.14.1 canonical `RectButton` adapter probe、嘗試透過`onPress`更新React state，並提供可由UI automation辨識的`Run tap gesture` target；它不宣稱adapter callback已成功。Final HAP中exact marker與初始`Gesture callback count=0`可見，對實際RectButton target做一次有界tap，單次 tap 後仍為 `Gesture callback count=0`；route後process/ability存活且fatal=0。因此route stability是pass，callback action blocked，沒有嘗試第四種API或把marker冒充callback evidence。

## Fresh-build provenance 與不採信證據

- Final d95 candidate的七個project都從source sample fresh materialize到新短路徑；沒有沿用舊`harmony/.cxx`、`build`或HAP artifacts。共用pnpm store不改變project build cache freshness。
- 每個 project安裝後都直接檢查 installed toolkit中的 final tarball contract；screens alias/app-key entry與實際 capability相符，再執行 init/sync/bundle/HAP。
- d95以前的tarball、HAP、runtime、重用build cache結果，以及每次gesture hypothesis留下的Wave A HAP，都移到`superseded/`並明確不採信。被中斷或同時存在的非authoritative Wave A runner output也只保留為診斷，不進入本表。
- 重用舊native cache曾造成appspawn SIGSEGV；control HAP與fresh materialize對照證明為stale-cache harness issue。Final matrix全部使用fresh materialize結果。
- Corrected fatal matcher另行重掃7個final basic-runtime hilog，TypeError/component-error等白屏pattern均為0；先前marker-only的誤判不進入final matrix。
- `examples/`與`fixtures/`沒有runner生成的殘留；debug/release build後的可版本化build profile沒有殘留password fields。

- packed consumer：安裝實際 packed tarball的 production graph，publish hard gate要求並取得 `critical=0`。
- workspace/examples：開發與sample graph仍有兩個既有 upstream critical，分別是 `GHSA-w7jw-789q-3m8p`（root Expo / React Native CLI的 `shell-quote` path）與 `GHSA-23hp-3jrh-7fpw`（official app-shell RNOH CLI的 `tar` path）。它們不是 packed consumer critical，也沒有被隱藏或改寫成 allowlist。

## 工具與可重現命令

本地工具版本：Node `20.19.6`、pnpm `10.32.1`、DevEco Studio `6.0.2`、ohpm `6.0.1`、hdc `3.2.0c`。Signing只驗證 config key structure、material existence與build後secret restore；本記錄不包含任何password、key、profile/certificate內容或target id。

```bash
# 單次pack；七個project重用同一路徑與同一SHA-256
pnpm pack --pack-destination <temp-root>/final/pack
pnpm add --ignore-scripts --save-dev <temp-root>/final/pack/expo-harmony-toolkit-2.0.0-next.0.tgz

# 每project portable/build contract
pnpm exec expo-harmony doctor --project-root . --target-tier <tier> --json
pnpm exec expo-harmony init --project-root . --force
pnpm exec expo-harmony sync-template --project-root . --force
pnpm exec expo-harmony sync-template --project-root . --force
pnpm exec expo-harmony bundle --project-root .
pnpm exec expo-harmony build-hap --project-root . --mode debug
pnpm exec expo-harmony env --json
pnpm exec expo-harmony build-hap --project-root . --mode release

# simulator basic runtime與route證據；實際bundle/ability由temp identity讀取，不寫入本記錄
hdc install -r <signed-release-or-bounded-simulator-variant.hap>
hdc shell aa start -a EntryAbility -b <temp-bundle>
hdc shell pidof <temp-bundle>
hdc shell aa dump -r
hdc shell uitest dumpLayout -p <remote-layout> -b <temp-bundle>
hdc shell hilog -x -P <pid>

# repository final gates
pnpm exec jest --runInBand tests/docs.test.ts tests/build.test.ts
pnpm build
pnpm test
pnpm pack:check
EXPO_HARMONY_RELEASE_CHANNEL=next EXPO_HARMONY_RELEASE_SKIP_HAP=1 CI=1 pnpm release:check
```
