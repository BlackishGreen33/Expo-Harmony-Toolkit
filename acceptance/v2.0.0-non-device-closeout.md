### 三個 action blocker 的修正證據

- File System：renderer 改為以 `openSync`、`writeSync`、`readSync`、`closeSync` 完成一次有界 roundtrip，route 以單一 action 執行 write/read/cleanup。source-fresh debug HAP 點擊後顯示 `File roundtrip OK. write/read/cleanup=pass`。
- Media Library：renderer 直接橋接 `RNCCameraRollPermission`，把 native permission code 映射成穩定字串。source-fresh debug HAP 從 `Permission lookup has not run.` 進入 action 後顯示 `Media permission status=denied.`；`denied` 是模擬器權限狀態，不是 failure，也不代表真實相簿讀寫。
- Gesture Handler：根因是 Metro 將 canonical JS 入口強制 alias 到 adapter package root，繞過 adapter 的 `redirectInternalImports`。啟用 gesture capability 時不再建立這個 root alias，route 使用 adapter 相容的 `TapGestureHandler` state callback。source-fresh debug HAP 中初始 `Gesture callback count=0`，對 target 單次 tap 後顯示 `Gesture callback count=1`，process/ability 存活且 corrected fatal matcher 為 0。

這三項都只關閉 simulator action blocker；`simulator pass 不是 device pass`，且真機權限、檔案系統與手勢語義仍保持 deferred。

- d95 以前的 tarball、HAP、runtime、重用 build cache 結果，以及 gesture 診斷過程留下的中間 Wave A HAP，都明確不採信。被中斷或同時存在的 non-authoritative runner output 只保留為診斷，不進入本表。
- 重用舊native cache曾造成appspawn SIGSEGV；control HAP與fresh materialize對照證明為stale-cache harness issue。Final matrix全部使用fresh materialize結果。
- Corrected fatal matcher另行重掃7個final basic-runtime hilog，TypeError/component-error等白屏pattern均為0；先前marker-only的誤判不進入final matrix。
- `examples/`與`fixtures/`沒有runner生成的殘留；debug/release build後的可版本化build profile沒有殘留password fields。
