### 錄影

- 已在系統 UI 允許麥克風。公開 `next.4` 拒絕錄影，回報 `Camera has no YUV video profile supported by AVRecorder.`。
- 實際 video-mode capability 只提供 `RGBA_8888`（format `3`）、`1280×720`、`30–60 fps`；photo mode 的 video profiles 為空。
- 隔離試驗允許 RGBA profile 後，檔案開啟與 `createAVRecorder` 成功，但 `prepare` 拒絕：BusinessError `5400103`，`IO error happened due to Prepare.`。移除音訊來源／音訊 profile 的純影片試驗仍在同一步失敗。
- `AVRecorder.getAvailableEncoder()` 只回傳 AAC `audio/mp4a-latm` 音訊 encoder，沒有影片 encoder；僅留下 `0-byte` MP4，沒有可播放錄影產物。這是當前模擬器的能力限制證據，不能據此宣稱 RGBA fallback 已驗證可用。
- [官方錄影範例](https://github.com/openharmony/docs/blob/master/en/application-dev/media/camera/camera-recording.md)依裝置能力選 profile；未提供影片 encoder 的本環境不足以驗收其他 profile。正式 adapter 的 YUV 選擇維持原樣，其他格式的相容性仍待有編碼能力的環境驗證。

### 拍照與生命週期

- 重裝上節原始 SDK 57 公開套件 HAP，規劃連續五輪 pause → paused → resume → running → 拍照。第一輪等候 `35 秒`（超過原生 `30 秒` timeout）仍無新 JPEG，UI 顯示 `Camera photo capture timed out. Remount CameraView before retrying.`；未把後四輪記為通過。
- 接著 force-stop／冷啟動直接拍照也逾時，失敗不只發生於 pause／resume。host qemu 日誌最後持續影像幀在 `22:27:34`；`22:42:10` 再次開啟 Mac 攝影機後沒有新 frame callback。
- 用官方 Emulator CLI 停止並重新啟動同一 instance，`23:11:17` 確認 guest boot completed 與攝影機授權。原始 HAP 冷啟動後，`23:20:37` host 再次開啟攝影機，仍無新 frame callback；拍照等候 `35 秒` 後仍無新 JPEG。
- 逾時後 CameraService active cameras 為 `0`，清理後沒有 client session。這證明有釋放資源，不證明預覽／拍照穩定性。

拍照曾取得成功產物，但後段在 host 停止送幀時持續失敗；尚不能把根因限定為 adapter 生命週期，也不能宣稱模擬器完全適配。錄影、完整權限拒絕／重試矩陣、鏡頭切換與正式簽名實機仍未通過驗收。

## 2026-09-20：錄影失敗清理與原生權限回歸

本節使用 Toolkit `2.0.0-next.5` 的本地 source 與重新生成的 native-capability HAP，尚不代表公開 npm 發布或正式簽名驗收。Expo／RN project lanes 沿用上表；Harmony runtime 仍為 RNOH `0.82.29`／React `19.1.1`。

- 相機測試由 4 項增為 16 項；先重現初始化失敗殘留 MP4、空影片誤報成功及非同步錯誤先於清理回傳，再修正為釋放 recorder／output／file、刪除失敗產物並保留原始錯誤。亦覆蓋五種原生權限狀態、授權後重建、拍照中卸載／late callback、逾時後 remount，以及錄影中卸載。
- Toolkit TypeScript build 與 202 tests／29 suites 通過。Expo 55／56／57 各自的 minimal 與 native-capability doctor／init／bundle／debug HAP build 全通過，共六條原生構建 lanes；這不等於全部 Expo／RN API 對齊。
- 三個 SDK 新 HAP 均以公開 SDK 測試簽名安裝，原生 foundation checks 通過：SecureStore async／sync／service 隔離／刪除、Asset 真實位元組與 hook、剪貼簿文字／HTML／URL／圖片、Device。安全區實測 top `38.8148`、bottom `27.8518`，frame `376.8889×816.5926`；未把初始值當作完整旋轉矩陣。
- 三個 SDK 均在系統設定撤銷 Camera／Microphone，冷啟動回報 `Camera permission is not granted.`，拍照回報 `Camera view is not mounted.`。只恢復 Camera 後錄影回報 `Microphone permission is not granted.`；兩項權限恢復後連續兩次錄影均明確回報沒有支援的 YUV profile，沒有誤報成功或卡在「已錄影」狀態。測試後兩項權限均恢復為 granted，背景清理後 active cameras／sessions 均為 `0`。SDK 56 另實際操作首次麥克風授權對話框並確認 granted。
